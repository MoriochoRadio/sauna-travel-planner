# 🔥 사우나 여행 코스 메이커 (Sauna Travel Planner)

한국 **사우나·찜질방·온천**을 축으로, **맛집·볼거리·숙소**를 엮어 맞춤형 여행 코스를 생성하는 인터랙티브 웹앱입니다.

> 지역 / 세부지역(시군구) / 기간 / 취향을 입력하면 → 일자별 타임라인(장소·시간·추천이유·팁·예상비용·추천지수)을 생성합니다.

### 👉 **[바로 사용하기 — sauna-travel-planner.vercel.app](https://sauna-travel-planner.vercel.app)**

## ❓ 왜 만들었나

사우나·온천을 좋아해서 여행을 자주 짜는데, 매번 같은 데서 막혔다.

**검색은 장소 하나만 알려준다.** "부산 온천"을 검색하면 목록이 나오지만, 그 앞뒤로 뭘 먹고 뭘 볼지는 따로 찾아야 한다. 결국 지도 앱과 블로그를 오가며 손으로 동선을 짠다.

**그리고 사우나 여행에는 고유한 제약이 있다.** 하루에 두 번 고온욕을 하면 오히려 피곤하고, 입욕 직후 장거리 운전은 위험하다. 식사 시간과 입욕 사이 간격도 필요하다. 일반 여행 플래너는 이런 걸 모른다.

그래서 **사우나를 축으로 두고 그 주변을 채우는** 도구를 만들었다. 지역·기간·취향만 입력하면 하루 흐름이 나오고, 웰니스 규칙(하루 1회 집중·수분 500ml·입욕 전후 버퍼)이 기본으로 들어간다.

## ✨ 기능

- **전국 커버리지**: 17개 시도 + 경주(독립 region), 230개 시군구 선택 가능
- **검증 큐레이션**: 공식 출처를 직접 확인한 대표 온천·찜질 시설 6곳. 장소마다 **확인한 출처와 검증일**, 이용 전후 유의사항, 주변 맛집·볼거리, 온열요법 참고 정보를 함께 제공. 운영 시간·요금처럼 자주 바뀌는 정보는 앱이 단정하지 않고 공식 출처로 넘김
- **여행 가이드**: "어떻게 쉬어야 하는지"를 다루는 가이드 3편 (부산 당일 온천, 첫 온천 체크리스트, 1박 자연 온천)
- **실시간 카카오 로컬 검색**: 선택 시군구 반경 10km 내 사우나/찜질방/온천/숙소를 실시간 조회 (키 필요, 무료)
- **온천·사우나 보유 숙소 자동 포함**: 2일차 이상이거나 숙소 옵션 켜면, 코스 마지막에 숙소를 자동 배치 (매일 다른 숙소)
- **추천지수(rating)**: 카카오는 리뷰/평점을 제공하지 않아, 가격대·온천보유·태그·정보완성도 기반 자체 산출 지표로 배지 표시
- **손수 짠 코스 + 규칙 기반 구성**: 검증한 장소로 직접 짠 추천 코스를 먼저 쓰고(부산·강원·충남·경기 당일, 경북 1박 2일), 없는 조합은 취향·추천지수·중복 배제 규칙으로 즉시 구성. 어느 쪽인지 코스 상단에 표시
- **웰니스 강조**: 하루 1회 사우나 집중, 수분 500ml 안내, 사우나 전후 버퍼
- **공유 URL**: 설정(지역/시군구/기간/취향)이 URL에 보존되어 복원·공유 가능
- **전국 지도 자유 선택**: 지역 지도에서 임의 시군구 클릭(마커 클러스터링) + 드롭다운 선택
- **데스크탑 2단 레이아웃**: 클릭 가능한 스테퍼로 이전 단계 바로 이동, 우측 고정 "선택 요약" 패널로 스크롤 없이 현재 선택 확인

## 🧱 기술 스택

- **Next.js 15.5** (App Router) · React 19 · TypeScript · Tailwind CSS
- **Zod** (입력/코스 스키마 검증) · **Vitest** (단위) · **Playwright** (E2E)
- **카카오 로컬 검색 REST API** (실시간 사우나/숙소, 무료·심사 없음)
- **tourAPI** (한국관광공사, 폴백 데이터 소스)
- **Leaflet + OpenStreetMap** (지도, API 키 불필요)

## 🚀 로컬 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

실시간 장소 검색을 쓰려면 환경변수를 등록합니다. 없어도 curated 장소로 정상 동작합니다:

```bash
cp .env.example .env.local
# KAKAO_REST_KEY=...        (카카오 개발자센터 REST API 키)
# TOURAPI_KEY=...           (선택, 폴백용)
```

> ⚠️ **보안**: 모든 키는 서버 환경변수(`.env.local`, Vercel/호스트 env)에서만 관리. 클라이언트 번들에 노출되지 않음.

## 🔒 보안 상태

`npm audit --omit=dev` 기준으로 관리한다. 마지막 점검일은 2026-08-18.

| 항목 | 상태 |
|---|---|
| Next.js 직접 권고(SSRF·DoS·캐시 혼동·서버 함수 노출 등 8건) | ✅ 해소 (15.5.23) |
| postcss(직접 의존) | ✅ 해소 (8.5.23+) |
| nanoid · sharp | ✅ 해소 (overrides로 패치 버전 고정) |
| next 내부에 중첩된 postcss 8.4.31 | ⚠ 잔존 |

잔존 항목은 Next 15가 `postcss: "8.4.31"`을 정확히 핀으로 박아 두어 npm overrides로 교체되지 않는다. 해당 권고는 CSS stringify XSS와 sourceMappingURL 경로 탐색으로, **빌드 시점에 공격자가 CSS 입력을 제어할 수 있을 때** 성립한다. 이 저장소의 CSS는 전부 자체 작성분이라 현재 구성에서는 악용 경로가 없다.

완전히 없애려면 Next 16(메이저) 업그레이드가 필요하다. 동작 중인 프로덕션 앱의 메이저 업그레이드라 별도 검증과 함께 진행할 사안으로 남겨 둔다.

## 🔑 핵심 설계 결정

- **카카오 리뷰 부재 대응**: 평점 대신 `* 추천지수(rating)`를 자체 산출해 배지 표시
- **숙소 자동 포함**: 다일차 여행 또는 옵션 켜짐 → 코스 마지막 stop(21:00)에 숙소 배치, 매일 다른 숙소 지향
- **fail-soft**: 외부 API 실패 시에도 curated 장소로 코스를 만들어 응답 (런타임 중단 없음)
- **무료 유지**: Vercel Free + GitHub Actions + 카카오 무료 티어

## 🧪 한계

- **큐레이션 코스는 5개 조합뿐이다.** 부산·강원·충남·경기 당일과 경북 1박 2일. 나머지는 규칙 기반으로 구성되며 손으로 짠 것만큼 촘촘하지 않다.
- **운영 정보를 확정하지 않는다.** 영업시간·요금은 자주 바뀌어서 앱이 단정하지 않고 공식 출처로 넘긴다. 대신 사용자가 한 번 더 확인해야 한다.
- **실시간 검색은 카카오 키가 필요하다.** 키가 없으면 curated 장소로만 동작한다.
- **이동 시간을 계산하지 않는다.** 시간표는 권장 순서일 뿐 실제 교통 상황을 반영하지 않는다.

## ✍️ 회고

**이 저장소에는 같은 서비스를 두 번 만든 기록이 남아 있다.**

2026-08에 AI 에이전트(Manus)에게 "온기행"이라는 이름으로 전면 재작성을 맡겼다. 돌아온 것은 tRPC·MySQL 풀스택으로 새로 쓴 앱이었고, **화면은 확실히 좋았다.** 딥그린과 테라코타를 쓴 시각 언어, 장소마다 붙은 공식 출처와 검증일, 온열요법 근거 인용, 여행 가이드.

그런데 **데이터가 6곳뿐이었다.** 원래 앱은 시군구 230개를 커버하고 카카오 실시간 검색과 규칙 기반 코스 생성을 갖고 있었다. 기능으로 보면 재작성본이 한참 뒤였다.

**그래서 되돌리지 않고 옮겨 왔다.** 원래 앱을 정본으로 유지하되, 재작성본에서 좋았던 것만 이식했다.

| 가져온 것 | 버린 것 |
|---|---|
| 검증 큐레이션 6곳 (공식 출처·검증일·과학 근거·주변 정보) | tRPC·MySQL 풀스택 구조 |
| 여행 가이드 3편 | 6곳짜리 장소 데이터 |
| 온기행 시각 언어 (딥그린·테라코타, WebGL 히어로) | 별도로 발행되던 정적판 |

재작성본은 `manus/ongihaeng-rebuild` 브랜치에 그대로 남겨 두었다.

**AI 코스 생성도 걷어냈다.** OpenRouter LLM으로 코스를 만들고 실패하면 규칙 기반으로 넘어가는 구조였는데, 실제로는 키가 없어 늘 규칙 기반으로 돌면서 **화면에는 "⚠ AI 생성 실패로 기본 코스를 표시합니다"라고 떴다.** 정상 동작하는 경로를 실패로 알리고 있었던 셈이다. 매번 달라지는 생성 결과보다 검증한 장소로 미리 짜 둔 코스가 품질이 일정해서, LLM 경로를 없애고 손으로 짠 코스 5개로 바꿨다.

**배운 것.**

1. **"전면 재작성"은 대부분 손해다.** 화면 하나 때문에 시군구 230개를 6곳으로 바꿀 수는 없다. 좋았던 것만 골라 옮기는 편이 낫다.
2. **fail-soft가 침묵 실패를 가린다.** 폴백이 잘 동작해서 서비스는 멀쩡했지만, 그 때문에 AI가 몇 주째 안 돌고 있다는 걸 몰랐다. 폴백에도 상태 표시가 필요하다.
3. **"실패"라는 단어를 함부로 쓰지 않는다.** 정상 경로에 경고 문구를 달아 두면 사용자는 고장 난 서비스로 읽는다.
