# 접근성 QA 기록

## 검증 범위

홈의 장소 탐색·필터·AI 코스 생성, 장소 상세의 저장·플랜·방문 기록, 마이페이지의 플랜 편집과 모바일 하단 탐색 막대를 대상으로 접근성 단서를 점검했다.

| 항목 | 적용 근거 | 확인 결과 |
|---|---|---|
| 키보드 포커스 | 전역 `:focus-visible` 외곽선 | 버튼, 링크, 입력, 필터가 마우스 없이도 현재 위치를 드러내도록 구현했다. |
| 컨트롤 라벨 | 저장 버튼, 플랜 장소 추가·삭제·순서 조정, 모바일 메뉴에 `aria-label` | 시각적 아이콘만 있는 동작의 이름을 보조기술에 제공한다. |
| 오류 알림 | 홈 장소 로딩, 장소 상세, 마이페이지, AI 코스 생성에 `role="alert"` 또는 `aria-live` | 네트워크·추천 실패 시 원인과 다음 행동을 문장으로 제공한다. |
| 색상만으로 의미 전달 금지 | 장소 유형 텍스트 배지, 지도 핀의 숫자, 버튼 텍스트 | 색상과 함께 텍스트·숫자·아이콘을 병행한다. |
| 모바일 터치 | 하단 메뉴, 40px 이상 저장 버튼, 여유 있는 필터·CTA 높이 | 작은 화면에서 주요 경로를 한 손으로 찾을 수 있게 구성했다. |

## 자동화 근거와 잔여 점검

`client/src/accessibility.test.ts`는 포커스 스타일, 핵심 인터랙션 라벨, 오류 공지 코드가 제거되지 않도록 검사한다. 실제 배포 전에는 VoiceOver 또는 TalkBack을 이용한 로그인·저장·플랜 편집의 전체 흐름을 한 차례 수동 점검하고, 지도 공급자가 제공하는 접근성 기능도 별도로 확인해야 한다.
