# 온기행 GitHub 중심 개발 운영 기준

## 기준 저장소와 브랜치

온기행의 모든 소스·문서·QA 기록은 GitHub 저장소를 기준으로 관리한다. `qa/phase-1-baseline`은 현재 풀스택 원본과 정적판 원본을 함께 보존하는 기본 개발 브랜치이며, `gh-pages`는 서버 없이 실행되는 공개 정적판만 포함하는 배포 브랜치다.

| 경로 | 역할 | 변경 시 필수 확인 |
|---|---|---|
| `qa/phase-1-baseline` | 풀스택 원본, 정적판 원본, 테스트, 문서 | 타입 검사·테스트·빌드·README·QA 기록 |
| `gh-pages` | GitHub Pages 공개 파일 | `index.html`·자산 동기화·공개 URL 렌더링 |
| `docs/` | 운영 범위, 콘텐츠 출처, QA 근거 | 기능 제외 범위와 변경 사유 최신화 |

## 변경·배포 절차

정적판을 변경할 때는 `client/public/github-pages/index.html`과 `docs/index.html`을 함께 갱신하고, 자동 테스트·타입 검사·빌드를 수행한다. 그 뒤 검증된 정적 HTML과 필요한 자산만 `gh-pages` 브랜치에 반영한다. 공개 URL에서 렌더링·핵심 상호작용·자산 응답을 확인한 뒤, 소스 브랜치에는 QA 기록과 변경 커밋을 남긴다.

풀스택 원본의 기능은 정적판과 혼동하지 않도록 별도 범위로 관리한다. 로그인, 서버 저장, AI 코스, 공유, 관리자 기능은 정적판의 약속 범위가 아니며, 외부 DB·인증·API 이전 계획이 확정될 때만 별도 기능 단계로 진행한다.

## 장소 정보 갱신 주기

정적판의 모든 장소는 `verifiedAt`과 `reviewBy`를 함께 기록한다. `official` 상태의 정보는 확인일로부터 **90일 이내**, `curation-draft` 상태의 정보는 **30일 이내**에 공식 링크와 핵심 이용 조건을 재검토한다. 요금·운영 시간·휴장·예약·시즌 시설에 관한 변경 제보가 있거나 공식 링크 응답이 실패하면, 예정일과 관계없이 즉시 재검토한다.

| 갱신 단계 | 필수 확인 | 반영 파일 |
| --- | --- | --- |
| 공식 링크 점검 | HTTPS 응답, 운영 주체, 안내 페이지 연결 | 정적 카탈로그·공개 QA |
| 핵심 이용 정보 점검 | 운영 시간·요금·이용 조건·시즌 공지 | `operatingNote`, `verifiedAt`, `reviewBy` |
| 상태 판단 | 확인 근거가 충분하면 `official`, 불완전하면 `curation-draft` 유지 | `status`와 카드 배지 |
| 배포 감사 | 자동 테스트·빌드·공개 페이지 렌더링 | `docs/index.html`, `gh-pages` |

정적판의 검토일은 운영 점검 목표이며, 실제 방문 전 최신 정보는 항상 카드의 공식 링크에서 다시 확인하도록 안내한다.

## 다음 정적판 우선순위

| 우선순위 | 개선 과제 | 사용자 가치 | 배포 영향 |
|---|---|---|---|
| P0 | 여행 목록을 텍스트로 복사하고 다시 불러오는 로컬 백업 | 브라우저 변경·초기화 전에도 계획을 보관 가능 | 정적 HTML만 갱신 |
| P0 | 장소 정보 갱신일·검증 상태의 정적 표시 | 정보 신뢰도 향상 | 콘텐츠 데이터·카드 갱신 |
| P1 | 일정 항목의 메모·순서 변경 | 단순 목록을 여행 계획으로 확장 | localStorage 스키마 확장 |
| P1 | 장소별 권리 확인된 사진과 출처 표기 | 탐색 경험 향상 | 이미지 자산·출처 기록 필요 |

다음 구현 단계는 P0인 **여행 목록 내보내기·복원**이다. 이 기능은 서버 없이 동작하고, 현재 로컬 일정 기능을 잃지 않으면서 사용자가 직접 백업할 수 있게 한다.
