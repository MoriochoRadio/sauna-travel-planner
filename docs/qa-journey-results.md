# 핵심 사용자 경로 및 반응형 QA 결과

## 검증 화면

홈 탐색(`/`), 장소 상세(`/places/spaland-centum-city`), 마이페이지(`/me`)를 데스크톱 1280px와 모바일 390px에서 확인했다.

| 경로 | 데스크톱 결과 | 모바일 결과 | 판정 |
|---|---|---|---|
| 홈 탐색 | 히어로, 필터, 장소 카드, AI 코스 입력, 지도, CTA가 순서대로 표시됨 | 카드·필터·AI 입력이 한 열로 정리되고 정보가 잘리지 않음 | 통과 |
| 장소 상세 | 핵심 정보·지도·이용 팁·과학 근거·주변 연계가 명확하게 분리됨 | 지도·정보 카드·CTA가 터치 가능한 크기로 유지됨 | 통과 |
| 마이페이지 | 저장·플랜·방문·추천 이력의 빈 상태가 명확함 | 긴 빈 상태도 자연스러운 세로 흐름을 유지함 | 통과 |

## QA 관찰

지도 공급자 스크립트를 불러올 수 없는 QA 환경에서는 번호 핀과 점선 동선을 가진 대체 지도 화면이 표시됐다. 따라서 지도 영역이 비거나 기능의 의미가 사라지지 않는다. 현재 빈 마이페이지는 기능 오류가 아닌 신규 사용자 상태이며, 각 상태에서 다음 행동을 안내한다.

## 실제 요청 및 상태별 검증

| 경로 | 검증 방식 | 결과 |
|---|---|---|
| 지역·분위기 필터 | `부산` + `세련된` 조합의 공개 API 요청 | 스파랜드 센텀시티 1건만 반환되어 다차원 필터 교집합이 확인됐다. |
| AI 코스 생성 | 공개 `travel.itinerary.generate` 실제 요청 | 구조화된 2개 stop의 AI 코스를 반환했고, `generatedWith: ai`를 확인했다. |
| 비로그인 상태 | 모바일 헤더·마이페이지 빈 상태 확인 | 저장 유도와 로그인 진입점, 설명형 빈 상태가 표시됐다. |
| 로그인 사용자 경로 | 보호 라우터 통합 단위 테스트 | 즐겨찾기와 플랜 생성·장소 추가 시 서버 컨텍스트의 사용자 ID만 전달되는 것을 확인했다. |
| 플래너 정렬·메모 | 서버 유닛 테스트와 UI 코드 검토 | 클라이언트 위치값을 수신하지 않고 서버의 최대 위치+1 규칙을 사용하며, 순서·메모·삭제 절차가 보호 라우터에 연결돼 있다. |

QA 목적상 테스트 요청은 공개 추천 경로와 모의 인증 컨텍스트로 한정했다. 실제 사용자 계정의 저장·방문·플랜 데이터를 임의로 생성하지 않았으며, 운영 전에는 별도 QA 계정으로 해당 데이터 영속화 흐름을 한 차례 점검하는 것을 권장한다.

## 로그인 세션 상호작용 QA 추가 결과

실제 로그인 세션에서 스파랜드 센텀시티를 즐겨찾기에 저장하고, 해당 장소를 새 `부산에서 보내는 느린 하루` 플랜으로 생성한 뒤 플랜에 추가했다. 새로고침 이후 즐겨찾기 1건과 플랜 1건·장소 1건이 다시 표시돼 저장·플랜 생성·장소 추가의 영속성을 확인했다. 초기 마이페이지는 병렬 조회가 완료되기 전 0건을 잠시 표시했으나, 이후 데이터가 정상 반영되는 비차단 로딩 상태였다.

메모 입력의 기존 blur 저장 방식은 실제 브라우저 입력 뒤 영속되지 않는 사례가 확인됐다. 이를 명시적인 `저장` 버튼 및 Enter 동작으로 변경했으며, 후속 회귀 검증은 브라우저 확장 응답 지연으로 재시도가 필요하다. QA 중 생성한 저장·플랜 데이터는 로그인한 사용자 계정에 남아 있다.

## 개선 후보

브랜드 시각 언어를 상세·마이페이지까지 확장하고, 히어로 이미지에 집중된 감각적 밀도를 장소 카드와 빈 상태에도 분산하는 개선이 유효하다. 이는 기능 결함이 아니라 다음 디자인 고도화 단계로 분류한다.
