# 온기행 전체 QA 및 단계별 형상관리 계획

## 목적

이번 QA는 화면이 보이는 수준을 넘어 탐색, AI 코스, 지도, 개인 여행 기록이 오류·권한·반응형 환경에서 일관되게 동작하는지 확인하는 안정화 절차다. 각 단계는 독립적으로 검증하고, 결과 문서와 관련 코드만 한 묶음으로 GitHub 브랜치에 반영한다.

## 단계와 통과 기준

| 단계 | 검증 범위 | 통과 기준 | GitHub 커밋 규칙 |
|---|---|---|---|
| 1. 기준선 수립 | QA 계획, 저장소·브랜치, 현재 빌드 기준 | 원격 브랜치와 QA 문서가 준비됨 | `chore(qa): establish QA baseline` |
| 2. 자동 QA | 테스트, 타입, 프로덕션 빌드, 정적 코드 점검 | 모든 자동 검사 통과, 경고는 분류 기록 | `test(qa): add automated audit coverage` |
| 3. 사용자 흐름 QA | 탐색·상세·AI·지도·개인 기능의 화면·상태 검증 | 데스크톱·모바일에서 핵심 경로와 빈·오류 상태 확인 | `test(qa): record critical journey validation` |
| 4. 보완·회귀 | 발견 결함의 수정과 회귀 검증 | 결함별 재현·수정·회귀 근거 기록 | `fix(qa): harden <scope>` |
| 5. 종료 보고 | 결과, 잔여 위험, 다음 우선순위 | 체크리스트 종료 및 최종 빌드 통과 | `docs(qa): publish stabilization report` |

## 핵심 사용자 경로

사용자는 홈에서 지역·분위기·시설·예산·동행 필터를 조합해 장소를 탐색할 수 있어야 한다. 이어서 AI 코스 입력, 코스 결과와 지도 동선, 장소 상세의 과학 근거와 주변 연계 정보를 확인한다. 로그인 상태에서는 저장, 플랜 생성·장소 추가·순서 변경·메모, 방문 기록, 추천 이력까지 일관된 상태로 이어져야 한다.

## 품질 원칙

모든 단계에서 개인정보·외부 공개·운영 데이터를 임의로 생성하지 않는다. 실제 지도 공급자가 제한되는 환경에서는 사용자에게 빈 화면을 보여 주지 않고 동선 대체 지도를 제공한다. AI 결과는 정해진 큐레이션 장소와 안전한 폴백 범위 밖의 사실을 만들지 않도록 검증한다. GitHub에는 기존 `main`을 직접 변경하지 않고, 우선 QA 전용 브랜치로 반영해 원본 프로젝트를 보호한다.
